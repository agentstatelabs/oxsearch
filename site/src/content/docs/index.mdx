## Semantic search in a dozen lines

<Example file="crates/oxsearch/examples/quickstart.rs" />

A struct is the document type. `#[derive(Document)]` builds its index mapping, `semantic_text` included, and gives it field handles: `Passage::TEXT.semantic(…)` is a semantic query on that field, and a field of the wrong type offers no such query. The search reads hits back as `Passage`.

## Why oxsearch

<CardGrid>
	<Card title="Generated from the specification" icon="seti:rust">
		Every type and endpoint comes from the Elasticsearch specification, pinned to one commit, and is never edited by hand. CI generates the code again and fails if it differs. Each area is its own crate behind a feature, so an application compiles only what it uses.
	</Card>
	<Card title="Typed AI search" icon="magnifier">
		Retrievers, `semantic`, `knn` and `sparse_vector` queries, `semantic_text` mappings and the inference API, as types. Where the cluster's license doesn't include server-side fusion, `oxsearch::fusion` fuses on the client.
	</Card>
	<Card title="A way out everywhere" icon="random">
		Your own endpoints go through the same client. A query, retriever or value the types don't know is a `Raw` variant, and `Client::send_raw` sends anything at all.
	</Card>
	<Card title="Tested against Elasticsearch" icon="approve-check">
		Each endpoint is checked against the specification's own examples, and an area counts as supported only once the integration tests run it against Elasticsearch, on the Basic license and a trial.
	</Card>
</CardGrid>
