## Aggregations

<Example file="crates/oxsearch/examples/analytics.rs" region="aggregations" />

`Agg` builds the common bucket, metric and pipeline aggregations, `.sub()` nests one under another, and `Aggs` names them for the request. Sent with `typed_keys`, the results read back as `Aggregates`, and `Results` picks them out by name: `value`, `stats`, `terms`, `histogram`, `date_histogram`, `ranges`, `filters`, `percentiles`, `top_hits`, and the same in each bucket's own sub-aggregations.

Every aggregation the specification describes is a generated type, for those the builders don't cover; `Agg::of` takes any of them.

## ES|QL

<Example file="crates/oxsearch/examples/analytics.rs" region="esql" />

<Example file="crates/oxsearch/examples/analytics.rs" region="row" />

`Esql` builds the query: `FROM`, `WHERE`, `EVAL`, `KEEP`, `DROP`, `RENAME`, `SORT`, `LIMIT`, `STATS … BY`, `MV_EXPAND`, `FORK` and `FUSE`. Values are sent as parameters, never written into the query's text, and identifiers are quoted.

`fetch` reads each row into your own type by column name. A dotted column, such as `author.name`, fills a nested struct, and a column missing or of the wrong type fails with `Error::Row`, which names the row and the column. With the `esql-arrow` feature, `fetch_arrow` reads the results as Arrow record batches instead.
